# Chroma Context-1

**Source:** https://www.trychroma.com/research/context-1
**Authors:** Hammad Bashir, Kelly Hong, Patrick Jiang, Zhiyi Shi (Chroma)
**Released:** March 2026
**Weights:** https://huggingface.co/chromadb/context-1 (Apache 2.0)
**Code:** https://github.com/chroma-core/context-1-data-gen

## Overview

Context-1 is a 20B-parameter language model purpose-built for **multi-turn agentic retrieval**. It operates as a retrieval subagent: given a high-level query, it decomposes it into subqueries, iteratively searches a corpus across many turns, and returns a ranked set of supporting documents to a downstream reasoning model. The reasoning model never sees the corpus directly.

The architectural choice — separation of search from generation — is what makes the cost story work. A 4x parallel Context-1 rollout, fused with reciprocal rank fusion, is cheaper than a single call to a frontier model.

## Architecture and Training

- **Base model:** [gpt-oss-20b](https://arxiv.org/abs/2508.10925), adapted via LoRA.
- **Training:** SFT on Kimi K2.5 rollouts (filtered by trajectory / output recall) followed by RL with verifiable rewards using [CISPO](https://arxiv.org/abs/2506.13585) (a GRPO variant).
- **Training data:** 8,000+ synthetic tasks across web, finance, legal, and email domains, generated by an LLM agent with extraction-based quote-pair verification (>80% human-judge alignment).
- **Serving:** vLLM with MXFP4 quantization on a single Nvidia B200; 400–500 tok/s end-to-end.

## Tools

The agent has four tools exposed via an observe-reason-act loop:

| Tool | Purpose |
| --- | --- |
| `search_corpus(query)` | Hybrid BM25 + dense via reciprocal rank fusion, reranked, top-k within token budget |
| `grep_corpus(pattern)` | Regex search, up to 5 matching chunks |
| `read_document(doc_id)` | Reranked + truncated to fit remaining budget |
| `prune_chunks(chunk_ids)` | Removes chunks from the agent's view (full trajectory retained for reward) |

A separate exclusion mechanism tracks every chunk ID encountered across prior search calls and suppresses duplicates in subsequent searches.

## Token Budget and Self-Pruning

The harness binds the context to a hard token budget `T_budget`. Three layered mechanisms:

- **Continuous visibility** — token usage is appended to every observation.
- **Soft threshold** at `T_budget / 2` — harness suggests pruning or concluding.
- **Hard cutoff** between `T_budget / 2` and `T_budget` — only `prune_chunks` is accepted.

The agent actively decides which chunks to keep or discard via `prune_chunks`. The harness preserves the unpruned trajectory so that the reward can credit the agent for documents it encountered even if they were later pruned. This is the [trajectory-recall reward term]([[Concepts/trajectory-recall-reward]]).

## Reward Design

```
r = clamp(0.7 · F_β + 0.3 · r_traj + r_fa − p_prune − p_turn, ε, r_pre)
```

- `F_β` — outcome term, β annealed from 4 → 2 (recall weighting 16x → 4x) over training.
- `r_traj` — trajectory recall; credits exploration beyond the final output.
- `r_fa` — binary +1.0 for retrieving a chunk directly containing the answer.
- `p_prune` — penalty for consecutive prune streaks longer than 3 (encourages batching).
- `p_turn` — penalty for trajectories exceeding 64 turns (encourages efficiency).

## Performance

On generated benchmarks (web, finance, legal, email) and public benchmarks (BrowseComp-Plus, SealQA, FRAMES, HotpotQA, HLE), Context-1 (4x) is comparable to frontier models despite being 10–100x smaller. On the most adversarial public benchmark (Seal0) frontier models with relaxed context still win, indicating Context-1 is not a universal substitute.

## Why It Matters

Context-1 is the first open-weights demonstration that **a small purpose-trained retrieval model can match frontier LLMs on retrieval quality** at a fraction of the cost. The implication is not that frontier models are unnecessary — they remain the answerer — but that *search* can be offloaded to a much cheaper specialized model. The published recipe (synthetic task generation, SFT + CISPO RL, self-pruning context, F_β curriculum) is reproducible and open.
