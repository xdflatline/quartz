# Post-Knowledge-Cutoff Temporal Prediction

**Source:** Liu, Han, Yu, Li, You, *Time-R1* (UIUC, arXiv:2505.13508v2, 2025-06-03) ([[Raw/arxiv-time-r1-temporal-reasoning-2025-06-03]]), Section 3.2.2
**Category:** Architecture Pattern (training data construction for post-cutoff tasks)
**Status:** Production-validated (empirical recipe with measured results)

---

## Overview

Predicting the timing of events that occur **after** an LLM's knowledge cutoff is one of the hardest tasks an LLM can be asked to do. By construction, the model has not seen the events during pre-training. Naively fine-tuning on real future events is impossible without breaking the cutoff; naively evaluating on real future events creates an unverifiable comparison.

Liu et al.'s recipe is a clean construction: align the baseline model's cutoff to a known date, train on a buffer of real events from a short pre-cutoff window plus synthetic events generated by a stronger model for the evaluation window, then evaluate on real events from that window. The synthetic-vs-real split prevents data leakage while still teaching the model to extrapolate.

## Core Content

### The setup

- **Base model knowledge cutoff:** Qwen2.5-3B-Instruct cutoff is end-of-2023.
- **Stronger baseline cutoff:** DeepSeek-V3-0324-671B cutoff is July 2024 (used for synthetic generation and as a comparison baseline).
- **Stage 2 evaluation window:** August 2024 – February 2025 (real future events, held out).

### The data construction

| Period | Data type | Source | Purpose |
|--------|-----------|--------|---------|
| Jan 2016 – Dec 2023 | Real NYT | NYT corpus | Stage 1 foundational comprehension training |
| Jan 2024 – Jul 2024 | Real news | Public news | Stage 2 in-distribution fine-tuning |
| Aug 2024 – Feb 2025 | **Synthetic** | DeepSeek-V3 generated from May–Jul 2024 news (~half the volume of real Jan–Jul 2024) | Stage 2 post-cutoff training |
| Aug 2024 – Feb 2025 | Real (held-out) | Public news | Stage 2 evaluation AND Stage 3 AvgMaxSim against real |

### Why synthetic for the evaluation period

The evaluation period (Aug 2024 – Feb 2025) needs to be a period the model hasn't seen during training. But the *test set* for that period must be real events (so that AvgMaxSim in Stage 3 is meaningful — comparing to actual news). Therefore:

- Training data for that period: synthetic (so the model isn't memorizing real events)
- Test data for that period: real (so plausibility evaluation is grounded)

The synthetic data is generated by DeepSeek-V3 conditioned on real news from the immediately preceding months (May–Jul 2024), so the synthetic events are temporally and contextually plausible without being copies.

### The empirical result

Despite using synthetic data for the most challenging post-cutoff period, Time-R1 ($\theta_2$, 3B) achieves the highest Stage 2 prediction score (0.7780), beating:

- DeepSeek-R1-671B (0.7503) — the larger model with broader reasoning
- DeepSeek-V3-0324-671B (0.7036) — the model used to generate the synthetic training data

The synthetic-data approach clearly transfers to real-event prediction. This is the load-bearing empirical claim of the paper: the synthetic-vs-real split is a workable recipe.

### When this pattern applies

The post-cutoff synthetic recipe applies whenever:

1. An LLM must be specialized for a period after its training cutoff.
2. Real ground-truth labels exist for that period (for evaluation).
3. A stronger model is available to generate plausible synthetic data for the evaluation period.

This is a common situation — knowledge cutoffs lag real events by 6–18 months for most production models, and any deployed LLM-based forecasting or temporal reasoning system needs to extrapolate across that gap.

## Key Insights

1. **Cutoff alignment enables fair comparison.** Anchoring the synthetic-generation model's cutoff to the strongest baseline (DeepSeek-V3, July 2024) ensures the baselines aren't handicapped by data they didn't see either.
2. **Synthetic is necessary for the evaluation period.** Real data for the evaluation period would leak into training; synthetic data avoids this while still teaching extrapolation.
3. **Synthetic generation must be contextually grounded.** Generating synthetic future events from immediately preceding real context produces plausible events that teach useful patterns.
4. **Synthetic-vs-real evaluation is honest.** Real held-out test set means the reported gains reflect real extrapolation, not synthetic-to-synthetic self-confirmation.
5. **The recipe is broadly applicable.** Any deployed LLM forecasting across its knowledge cutoff can use this pattern: train on real-buffer + synthetic-evaluation-period, evaluate on real-evaluation-period.
